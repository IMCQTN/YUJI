# 课堂演示流程

使用 assets/demo-corpus.jsonl 的原创虚构人物，避免展示私人聊天。林澈偏简洁、直接、轻微干幽默；唐宁偏轻快、展开更多、偶有表情。两人都能随场景变化，不能简化为“一个冷淡一个热情”。

## 演示 1：建档与依据

请求：“使用语迹，从演示语料为林澈建立档案。展示三条表达规则和出处。”

执行 corpus build、profile init，然后用训练集完善档案并 validate。可用 profile-example.json 作对照，但必须核对同一版本语料与 seed。展示真实训练引用和覆盖限制，不把摘录验证当成人工相似度结论。

## 演示 2：同一意思，不同人物

请求：“分别用林澈和唐宁的语气，回复：实验做了一整天，还是没弄出来，不想干了。”

各自建档、检索、独立生成。只展示两个回复，再开 director 说明信息顺序、句长和关心表达上的差异。不要提前写死标准答案。

## 演示 3：有来源的记忆与未知边界

先说：“我不喝咖啡，周五下午三点有课。”写入 session，按来源保存两项用户记忆。若后续邀请安排时间，不能再提周五三点，也不能把不喝咖啡归给角色。

再问：“你还记得我们去年在杭州第一次见面的那家店吗？”如果语料/会话从未给过，不发明店名。人物可以自然地表达不确定；不是每次都跳出角色写免责声明。

## 演示 4：关系/场景变化与分支

同一人物先回复朋友邀请，再写给老师的延期申请。展示声线连续而礼貌程度、信息密度变化。

从同一 revision 建 A/B 两条分支，分别尝试转移话题和具体道歉。展示不同剧情结果和来源，不宣称现实人物必然这么反应；主线 revision 不变。

## 演示 5：可检查的对照

使用 evaluate.py cases 导出未带参考回复的题；一个独立执行者仅用普通模仿提示，另一个用本 Skill。先固定输出，再 assess。展示自动分布差异及局限；如果有实际同学评审，再发匿名 A/B 表。

答辩要点：

- Skill 由核心指令、按需参考、可执行脚本、原创演示素材组成，生成依靠承载它的语言模型，不是另训练了一个大模型。
- 复杂性体现于有证据的档案、场景路由、检索、记忆归属、版本事务、防泄漏评测和反馈更新。
- 与一次普通提示比较，考察固定流程的可重复性；不声称只有 Skill 才能实现这些功能。
- 不保证任意人物完全还原。语料质量、场景覆盖和底层模型能力共同限制效果。
